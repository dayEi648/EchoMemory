# EchoMemory 前端整体重设计方案

## 1. 背景与问题

当前前端骨架更像“功能验证页”：一个页面承载首页、个人中心、管理后台、音乐占位等多个模块，并通过侧边栏按钮切换。这个结构适合早期联调，但不适合作为音乐平台客户端继续扩展。

核心问题：

- 信息架构混乱：平台级内容、账号设置、管理能力混在同一层导航。
- 首页价值不明确：“用户搜索”直接放在首页不符合音乐平台用户预期。
- 管理后台和个人中心过于显眼：这类入口应作为账户能力隐藏在头像菜单、设置入口或管理员工作台入口中。
- 视觉层次弱：当前页面缺少音乐平台应有的内容运营感、封面资产、播放器、榜单、歌单、推荐流和沉浸式浏览体验。
- 扩展性差：继续在一个 `App.tsx` 中堆页面，会让后续真实音乐、歌单、评论、社区、AI Agent 能力接入变得难维护。

## 2. 设计目标

本次重设计目标是把 EchoMemory 从“功能 demo”调整为“桌面音乐客户端”。

必须达成：

- 首页只展示音乐平台用户自然需要的内容：推荐、歌单、新歌、榜单、最近播放、AI 记忆推荐。
- 用户搜索从首页移除，改为全局搜索能力，搜索范围包括歌曲、歌单、专辑、用户，结果页按类型分栏。
- 个人中心隐藏到头像下拉菜单中，作为“我的主页 / 账号设置 / 编辑资料”的二级入口。
- 管理后台只对管理员显示，并隐藏到头像下拉菜单中的“管理后台”入口；普通用户和 VIP 不显示入口，直接访问也重定向到首页。
- 主界面采用音乐平台常见布局：顶部工具栏 + 内容主区 + 底部播放器 + 轻量侧边导航。
- 视觉参考网易云音乐、QQ 音乐、Bilibili 的成熟平台感，但不做直接复刻。
- 保持 Windows 桌面端优先，兼容 Tauri 窗口尺寸变化。

## 3. 产品信息架构

### 3.1 主应用结构

```
AppShell
├── TopBar
│   ├── 窗口拖拽区域 / 品牌标识
│   ├── 前进后退
│   ├── 全局搜索框
│   ├── 通知按钮
│   └── 用户头像菜单
├── SideNav
│   ├── 发现音乐
│   ├── 我的歌单
│   ├── 我的收藏
│   ├── 最近播放
│   └── AI 回声
├── MainContent
│   └── 当前路由页面
└── PlayerBar
    ├── 当前歌曲
    ├── 播放控制
    ├── 进度条
    ├── 音量
    └── 播放队列
```

### 3.2 路由规划

| 路由 | 页面 | 导航层级 | 说明 |
| --- | --- | --- | --- |
| `/` | 发现音乐 | 主导航 | 默认首页 |
| `/playlists` | 我的歌单 | 主导航 | 当前用户创建的歌单 |
| `/library` | 我的收藏 | 主导航 | 收藏歌曲、收藏歌单、关注内容 |
| `/history` | 最近播放 | 主导航 | 最近听歌、继续播放 |
| `/echo` | AI 回声 | 主导航 | AI Agent 记忆推荐、偏好画像 |
| `/search` | 搜索结果 | 全局搜索触发 | 按歌曲、歌单、专辑、用户分组 |
| `/profile/:userId` | 用户主页 | 头像菜单/搜索结果 | 展示公开资料和公开歌单 |
| `/account` | 账号设置 | 头像菜单 | 当前用户资料编辑 |
| `/admin` | 管理后台 | 管理员头像菜单 | 独立后台工作台，管理员可见 |

### 3.3 顶部头像菜单

头像菜单取代当前侧边栏的“个人中心”和“管理后台”入口。

普通用户 / VIP：

- 我的主页
- 账号设置
- 我的收藏
- 最近播放
- 退出登录

管理员 / 超级管理员额外显示：

- 管理后台

交互规则：

- `role=0/1`：不渲染“管理后台”菜单项。
- `role=2/3`：显示“管理后台”菜单项。
- 直接访问 `/admin`：非管理员重定向 `/`。

## 4. 页面设计

### 4.1 发现音乐首页

首页不承担用户搜索职责，而承担“让用户快速开始听歌”的职责。

首屏结构：

- 大幅推荐区：今日推荐、继续播放、AI 为你生成的回声歌单。
- 右侧紧凑信息：最近播放、今日心情标签、等级进度。
- 内容下探：热门歌单、新歌上架、排行榜、推荐音乐人。

推荐布局：

```
发现音乐
├── Hero 推荐区
│   ├── 今日推荐封面墙
│   ├── 主 CTA：播放今日推荐
│   └── 次 CTA：查看 AI 回声
├── 最近继续听
├── 为你推荐的歌单
├── 新歌 / 新专辑
├── 排行榜
└── 推荐音乐人
```

首页禁止出现：

- 单独的“用户搜索”模块。
- 管理用户、封禁用户等后台操作。
- 过多账号资料编辑入口。

### 4.2 全局搜索

顶部搜索框用于全站搜索，视觉参考网易云音乐和 Bilibili 的搜索体验。

搜索框状态：

- 未输入：展示最近搜索、热门搜索。
- 输入中：下拉即时建议。
- 回车或点击结果：进入 `/search?q=...`。

搜索结果页分组：

- 单曲
- 歌单
- 专辑
- 用户

用户搜索只作为搜索结果页的一组，不再占据首页。

### 4.3 我的歌单

用于管理当前用户创建的歌单。

页面组成：

- 当前用户歌单列表。
- 空状态引导创建第一个歌单。
- 分页浏览和进入歌单详情。

首期即使未接真实音乐 API，也应以高质量空状态和骨架数据呈现，而不是简单占位卡。

### 4.4 我的收藏

个人内容入口，不作为“个人中心”大卡片出现。

分区：

- 收藏歌曲
- 收藏歌单
- 关注音乐人
- 关注用户

### 4.5 最近播放

桌面音乐客户端的核心效率页。

内容：

- 最近播放列表。
- 按日期分组。
- 右侧显示播放统计和常听风格。

### 4.6 AI 回声

承接项目“围绕 AI Agent 的音乐平台”的差异化定位。

页面目标：

- 展示 AI 如何理解用户音乐偏好。
- 将情感标签、兴趣标签、听歌历史形成“回声画像”。
- 提供 AI 生成歌单、记忆片段、推荐理由。

模块：

- 回声画像卡片：偏好风格、情绪曲线、常听场景。
- AI 推荐歌单：带推荐理由。
- 记忆片段：某段时间、地点、情绪与音乐的关联。
- 后续可接入 LangGraph/RAG 工作流。

### 4.7 账号设置

从“主页面”降级为“头像菜单进入的设置页”。

结构：

- 基础资料
- 头像上传
- 城市、生日、简介
- 安全设置
- 账号状态提示

表单规则：

- 不在输入框旁提前展示校验规则。
- 后端返回错误后用 toast 或字段错误摘要提示。

### 4.8 用户公开主页

用户主页不是当前用户编辑页。

内容：

- 用户头像、昵称、等级、认证状态。
- 公开歌单。
- 公开动态或音乐足迹。
- 关注按钮。

敏感字段不展示：email、phone、status、safety_score 等。

### 4.9 管理后台

管理后台应从主音乐客户端体验中抽离，作为独立工作台。

入口：

- 仅管理员头像菜单显示“管理后台”。

布局：

```
AdminShell
├── AdminTopBar
│   ├── 返回主站
│   ├── 管理后台标题
│   └── 当前管理员
├── AdminSideNav
│   ├── 用户管理
│   ├── 音乐导入
│   ├── 字典维护
│   ├── 内容审核
│   └── 系统状态
└── AdminContent
```

后台风格：

- 更接近 SaaS 管理台。
- 信息密度高于用户端。
- 表格、筛选器、批量操作、状态标签明确。
- 不使用音乐首页的大封面和娱乐化视觉。

## 5. 视觉方向

### 5.1 参考风格

网易云音乐：

- 明确的音乐平台结构。
- 播放器常驻底部。
- 首页以推荐和歌单为中心。
- 强调红色品牌记忆点，但 EchoMemory 不直接使用网易云红。

QQ 音乐：

- 大面积清爽留白。
- 专辑封面网格和圆角卡片。
- 会员、推荐、歌单模块的商业平台感。

Bilibili：

- 顶部搜索和用户菜单成熟。
- 内容流、分区、推荐卡片清晰。
- 轻量弹层、hover 反馈、互动状态丰富。

EchoMemory 的方向：

- 亮色主题，偏精致音乐客户端。
- 主色建议使用“深墨黑 + 回声珊瑚 + 柔和青绿/紫色点缀”。
- 不采用单一红色或单一蓝紫渐变，避免像模板。
- 封面图、歌单图、用户头像是主要视觉资产。

### 5.2 色彩系统

| Token | 建议值 | 用途 |
| --- | --- | --- |
| `--color-bg` | `#fbfaf7` | 应用背景 |
| `--color-surface` | `#ffffff` | 面板、菜单 |
| `--color-surface-soft` | `#f3f0ea` | 次级区域 |
| `--color-ink` | `#161514` | 主文本 |
| `--color-muted` | `#77716a` | 次级文本 |
| `--color-border` | `#e7e1d8` | 分割线 |
| `--color-accent` | `#ff5b57` | 主操作、播放状态 |
| `--color-accent-2` | `#2bb3a3` | AI / 成功状态 |
| `--color-accent-3` | `#8d7cf6` | 回声画像点缀 |
| `--color-danger` | `#e5484d` | 危险操作 |

### 5.3 字体

推荐：

- 中文：`"Noto Sans SC"` 或系统默认中文字体。
- 英文/数字：`Inter`。
- 标题：600/700，避免过重。
- 控件文字：13-14px。
- 正文：14-16px。

### 5.4 圆角与阴影

- 封面卡片：12px。
- 菜单、弹层：12px。
- 按钮：8px 或 pill，按场景区分。
- 管理后台表格：6-8px，更克制。
- 阴影轻量，避免大面积漂浮卡片。

## 6. 组件体系

建议引入成熟组件和动效库：

- 路由：`react-router-dom`
- 数据请求：`@tanstack/react-query`
- 状态：`zustand`
- 组件基础：`radix-ui` 或 `shadcn/ui`
- 动效：`framer-motion`
- 图标：继续使用 `lucide-react`
- 虚拟列表：`@tanstack/react-virtual`
- 表格：`@tanstack/react-table`
- 播放拖拽条：Radix Slider

核心组件：

- `AppShell`
- `TopBar`
- `AvatarMenu`
- `SideNav`
- `PlayerBar`
- `SearchCommand`
- `CoverCard`
- `PlaylistRail`
- `SongRow`
- `UserMenuItem`
- `EmptyState`
- `AdminShell`
- `AdminDataTable`
- `PermissionGate`

## 7. 动效规范

动效目标是增强“桌面客户端质感”，不是炫技。

使用场景：

- 页面切换：轻微 fade + y 轴 8px。
- 菜单弹出：scale 0.98 → 1，opacity 0 → 1。
- 封面 hover：封面轻微放大，播放按钮浮现。
- 播放状态：当前歌曲行显示动效 equalizer。
- 搜索建议：输入后列表平滑展开。
- AI 回声页：画像卡片和推荐理由分段出现。

无障碍：

- 尊重 `prefers-reduced-motion`。
- 所有 hover 反馈必须有键盘 focus 对应状态。

## 8. 首期实现策略

虽然最终目标是完整音乐平台体验，但首期仍可以分阶段落地。

### Phase 1：重建应用壳与导航

- 引入路由。
- 拆分 `App.tsx`。
- 建立 `AppShell`、`TopBar`、`SideNav`、`PlayerBar`。
- 移除首页用户搜索。
- 头像菜单承载个人中心、账号设置、管理后台、退出登录。
- 非管理员 `/admin` 重定向首页。

验收：

- 首页不出现用户搜索。
- 普通用户/VIP 主界面看不到管理后台入口。
- 管理员可从头像菜单进入管理后台。
- 底部播放器常驻。

### Phase 2：重做首页与搜索

- 首页展示推荐、歌单、新歌、榜单、最近播放。
- 顶部全局搜索进入搜索结果页。
- 用户搜索只在搜索结果中作为一类出现。

验收：

- 首页第一屏像音乐平台，而不是后台面板。
- 搜索体验符合用户预期。

### Phase 3：账号设置与用户主页

- 账号设置独立成页。
- 用户公开主页独立成页。
- 当前用户从头像菜单进入编辑资料。

验收：

- 个人资料编辑不再占据主导航。
- 用户公开资料不暴露敏感字段。

### Phase 4：管理后台独立化

- 管理后台使用 `AdminShell`。
- 用户管理表格化。
- 后续接音乐导入、字典维护、内容审核。

验收：

- 后台与用户端视觉明确区分。
- 后台入口权限完整。

### Phase 5：AI 回声体验

- 构建 AI 回声页。
- 用听歌历史、兴趣标签、情感标签形成可视化画像。
- 为后续 Agent/RAG 能力预留展示区。

验收：

- EchoMemory 有区别于普通音乐播放器的核心记忆点。

## 9. 成功标准

重构完成后应满足：

- 用户打开应用后第一感觉是“音乐平台”，不是“后台 demo”。
- 首页没有用户搜索、管理后台、个人资料编辑这类不合适的一线模块。
- 主导航只放高频音乐消费入口。
- 账号、管理、退出登录都收纳到头像菜单。
- 管理后台权限同时体现在入口渲染和路由保护。
- 页面拆分清晰，不再用单个组件承载所有模块。
- 视觉上达到成熟桌面音乐客户端水准。
- 动效轻量、稳定、不干扰听歌和浏览。

## 10. 不做事项

本设计不建议：

- 继续使用“一页多 tab”。
- 将管理后台放在普通侧边栏。
- 将个人中心放在主导航。
- 将用户搜索放在首页核心区域。
- 用大量说明文字解释功能。
- 继续使用低质占位卡作为主要页面内容。
