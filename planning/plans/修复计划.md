## 严重 BUG

### BUG-1：详情页收藏状态未从服务端初始化

| 属性 | 内容 |
|------|------|
| **优先级** | P0 |
| **位置** | `MusicDetailPage.tsx:30`、`PlaylistDetailPage.tsx:27`、`AlbumDetailPage.tsx:22` |
| **确认结果** | 成立。三个详情页均以 `useState(false)` 初始化 `collected`，加载详情后没有查询当前用户是否已收藏。 |
| **后端现状** | `collection.py` 只有收藏、取消收藏、分页列出收藏列表；`MusicOut`、`AlbumOut`、`PlaylistOut` 也没有 `is_collected_by_me` 字段。 |
| **影响** | 已收藏资源刷新详情页后仍显示“收藏”，用户可能重复点击；虽然后端收藏接口幂等，但 UI 状态错误。 |
| **合理修复建议** | 后端先补当前用户收藏状态语义，二选一：A. 在三个详情响应中增加 `is_collected_by_me`，详情接口按当前用户填充；B. 在 `collections` 下增加 `GET /collections/musics/{id}/status`、`/albums/{id}/status`、`/playlists/{id}/status`，返回 `{ "collected": boolean }`。前端再在详情加载时并行获取详情和状态，失败时保守显示未收藏并提示或静默降级。 |
| **测试要求** | 后端补服务测试覆盖已收藏/未收藏/目标不存在；前端补组件或 API 测试覆盖初始化为已收藏、点击取消后状态变化。 |

## 设计与状态管理问题

### DESIGN-1：API 实例与 tokenStore 管理分散

| 属性 | 内容 |
|------|------|
| **优先级** | P1 |
| **位置** | `authStore.ts:45-58`、`playerStore.ts:9-11`、`instances.ts:16-24`、`DiscoverPage.tsx:12` |
| **确认结果** | 原 P0 结论误判，但设计问题成立。生产环境不会因为多个 localStorage tokenStore 实例使用旧 token；问题在于 API 实例来源分散、测试注入 `_setTokenStore` 只影响 `authStore`，其它模块仍使用默认 localStorage tokenStore。`DiscoverPage.tsx` 还存在未使用的 `createLocalStorageTokenStore` 导入。 |
| **合理修复建议** | 建立单一 API factory/registry，导出 `getApis()`、`setApiTokenStoreForTest()` 或类似接口；`authStore`、`playerStore`、页面统一从 registry 获取 API。测试环境替换 tokenStore 时必须影响所有 API 实例。清理未使用导入。 |
| **回归风险** | 修改 API registry 会影响所有网络调用，应先补 `base.ts`/API 实例测试，再改调用方。 |

### DESIGN-2：AppShell 使用 pathname 作为动画 key 会强制重挂载页面

| 属性 | 内容 |
|------|------|
| **优先级** | P1 |
| **位置** | `components/layout/AppShell.tsx:16-23` |
| **确认结果** | 成立。`<motion.div key={location.pathname}>` 会在路径变化时卸载并重建 `<Outlet />` 内容。 |
| **影响** | 页面本地 state、未提交表单、局部滚动位置在路由切换时丢失。对详情页、搜索页、管理后台编辑弹窗等体验有潜在影响。 |
| **合理修复建议** | 不建议直接删除全部动画。优先用 `useOutlet()` + 路由级动画边界，或只对外层透明度做 CSS 过渡；需要确认哪些页面允许切换后丢弃草稿。 |
| **测试要求** | 增加路由切换回归：搜索页关键词/分页、管理表单输入、详情页返回行为。 |

### DESIGN-3：playerStore 的 Audio 生命周期由模块级变量隐式管理

| 属性 | 内容 |
|------|------|
| **优先级** | P2 |
| **位置** | `shared/stores/playerStore.ts:72-121` |
| **确认结果** | 成立但不阻塞生产功能。模块级 `audio` 和 `_listenersBound` 能避免普通重复绑定，但生命周期、测试隔离、Fast Refresh 清理都不清晰。 |
| **合理修复建议** | 将 Audio 与事件监听封装为可初始化/销毁的 player controller，并由 Zustand store 持有 controller 引用。测试中可注入 fake audio，热更新/卸载时有明确 cleanup。 |
| **回归风险** | 播放、切歌、播放历史上报都依赖该逻辑，修复时必须优先补 playerStore 单元测试。 |

## 交互与代码质量问题

### QUALITY-1：PlayerBar 进度条按下时可能触发重复 seek

| 属性 | 内容 |
|------|------|
| **优先级** | P2 |
| **位置** | `components/layout/PlayerBar.tsx:62-78`、`250-251` |
| **确认结果** | 成立，但不应列 P0。`onMouseDown` 内已调用 `handleProgressClick`，浏览器随后可能触发 `click`，导致同一位置 seek 两次。通常不会造成明显错位，但会产生重复状态更新。 |
| **合理修复建议** | 移除 `onClick`，统一用 `onPointerDown` / `pointermove` / `pointerup` 实现鼠标与触控；或保留 click 但在拖动路径中抑制后续 click。 |
| **测试要求** | 用组件测试或 Playwright 验证点击一次只调用一次 seek，拖动时进度跟随。 |

### QUALITY-2：CreatePostForm 卸载时未释放 object URL

| 属性 | 内容 |
|------|------|
| **优先级** | P2 |
| **位置** | `components/ui/CreatePostForm.tsx:32-34`、`43`、`69` |
| **确认结果** | 成立。选择图片后会创建 object URL；删除单张和提交成功会释放，但组件卸载或发布失败后离开页面不会统一释放剩余 URL。 |
| **合理修复建议** | 使用 `useEffect` cleanup 在组件卸载时释放当前 previews。注意避免 stale closure，可用 ref 保存最新 previews，或在 state updater 中集中释放。 |
| **测试要求** | mock `URL.createObjectURL` / `URL.revokeObjectURL`，覆盖删除、提交成功、卸载三种路径。 |

### QUALITY-3：base.ts 错误响应解析缺少运行时类型保护

| 属性 | 内容 |
|------|------|
| **优先级** | P2 |
| **位置** | `shared/api/base.ts:21-29` |
| **确认结果** | 成立。`response.json()` 可能返回 `null`、数组或字符串。当前代码直接按 `{ detail?: string }` 断言；当返回 `null` 且 `!response.ok` 时访问 `data.detail` 会抛 TypeError，掩盖真实 HTTP 错误。 |
| **合理修复建议** | 先把 JSON 结果存为 `unknown`，用运行时判断提取字符串型 `detail`；无法提取时使用默认“请求失败”。 |
| **测试要求** | 覆盖错误响应体为 `{ detail }`、`null`、字符串、非 JSON、204。 |

### QUALITY-4：ApiError 原型链兼容性增强

| 属性 | 内容 |
|------|------|
| **优先级** | P3 |
| **位置** | `shared/api/base.ts:3-10`、`apps/frontend/tsconfig.json:3` |
| **确认结果** | 原 P1 风险定级过高。当前编译目标为 `ES2022`，不是 ES5；当前代码也没有 `instanceof ApiError` 判断，只有 `err as ApiError`。 |
| **合理修复建议** | 可在 constructor 中补 `Object.setPrototypeOf(this, ApiError.prototype)` 并设置 `this.name = "ApiError"`，作为防御性兼容增强。该项可与 QUALITY-3 一起改。 |
| **测试要求** | 增加 `expect(new ApiError(...)).toBeInstanceOf(ApiError)`。 |

### QUALITY-5：SongRow 封面图片缺少加载失败 fallback

| 属性 | 内容 |

### QUALITY-6：PlayerBar 静音图标判断过于严格

| 属性 | 内容 |
|------|------|
| **优先级** | P3 |
